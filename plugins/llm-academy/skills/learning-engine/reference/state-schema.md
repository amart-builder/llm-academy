# LLM Academy: State Schema

This is the single source of truth for how learner progress is stored. Every command and agent reads and writes through this schema. Get it right and the academy remembers everything across sessions, machines, and reinstalls.

## Where state lives

```
STATE_DIR = ${LLM_ACADEMY_STATE:-$HOME/.llm-academy}
```

Resolve `STATE_DIR` from the `LLM_ACADEMY_STATE` environment variable, defaulting to `$HOME/.llm-academy` when unset. This resolution is mechanical: if `LLM_ACADEMY_STATE` is set, use its value verbatim. Never judge, question, or override it, and never fall back to `~/.llm-academy` while it is set. An unusual-looking path is not your concern; the user set it on purpose (for example a cloud-synced or backed-up folder, or an isolated directory for testing). The default must find your progress no matter what directory Claude Code was launched from. State is separate from the plugin code, so reinstalling or updating the plugin never touches your progress. All file paths below are relative to `STATE_DIR`.

Files:

```
~/.llm-academy/
├── learner-profile.json     # who you are, your track, your level per tier, your preferences
├── curriculum.json          # your personalized path (the machine source of truth)
├── curriculum.md            # human-readable mirror of the path (you can read this anytime)
├── progress.json            # XP, level, rank, streak, badges, global counters
└── sessions/
    └── 2026-07-10.md        # one journal entry per learning day
```

## Golden rules for writing state

1. **Read before you write.** Always read the existing file, modify the object in memory, write the whole thing back. Never blind-overwrite. Losing progress is the one unforgivable bug.
2. **Write valid JSON.** No trailing commas, no comments inside the `.json` files. If you are unsure, re-read what you wrote.
3. **Keep `curriculum.md` in sync with `curriculum.json`.** Whenever unit status changes, regenerate the markdown mirror from the JSON.
4. **Dates are ISO `YYYY-MM-DD`.** Use the current date from the session context; never invent dates. `lastSessionDate` and all spaced-rep dates are calendar dates (date-only), because streak and due-review logic compares whole days. A `lastUpdated` field may carry a full ISO-8601 timestamp if finer granularity is useful.
5. **If a file is missing, the learner is new.** Absence of `learner-profile.json` means run onboarding.

## learner-profile.json

Written once at onboarding, updated whenever a re-placement happens, the track switches, or preferences change.

```json
{
  "name": "Alex",
  "createdAt": "2026-07-10",
  "lastUpdated": "2026-07-10",
  "goal": "Understand how large language models actually work, well enough to explain ChatGPT end to end.",
  "track": "explainer",
  "specificAims": [
    "Explain embeddings and attention to a non-technical friend",
    "Understand why models hallucinate and what their limits are"
  ],
  "preferences": {
    "pace": "1hr",               // 1hr | 30min | sprint
    "vibe": "fun-but-sharp"      // fun-but-sharp | full-game | minimal
  },
  "levels": {
    // one entry per content tier. scale: 0 unknown, 1 novice, 2 advanced-beginner,
    // 3 competent, 4 proficient, 5 expert. Tier T6 is never scored (always elective).
    "T1": 0,
    "T2": 0,
    "T3": 0,
    "T4": 0,
    "T5": 0
  },
  "gaps": [
    "No mental model for what an embedding is",
    "Cannot yet say what attention does"
  ],
  "strengths": [
    "Comfortable with analogies and abstract ideas",
    "Strong intuition for probability"
  ],
  "assessments": [
    {
      "date": "2026-07-10",
      "itemsAsked": 9,
      "summary": "Complete beginner across the board, strong general reasoning. Start at u1.",
      "transcriptRef": "sessions/2026-07-10.md"
    }
  ]
}
```

Notes:
- **`track`** is `"explainer"` or `"builder"`. Chosen at onboarding, switchable anytime from the coach menu. On `explainer`, the curriculum omits every `track: builder` unit. On `builder`, everything is included. Switching recompiles the path (via the `curriculum-architect`) without discarding any already-mastered units.
- The **`levels`** map is keyed by content tier (`T1` through `T5`), not by unit. Placement scores each tier 0 to 5. A tier at 4 or 5 is treated as owned and compressed to confirmation checks; 0 to 2 is taught in full; 3 is taught gaps-only. There is no `projects` preference in this academy; the analogous choice is `track`.

## curriculum.json

The machine source of truth for the learning path. Generated by the `curriculum-architect` agent, updated by the daily loop as units progress.

```json
{
  "generatedAt": "2026-07-10",
  "lastUpdated": "2026-07-10",
  "version": 1,
  "track": "explainer",
  "units": [
    {
      "id": "u1",
      "tier": "T1",
      "title": "Everything becomes numbers",
      "summary": "Words and everything else turn into vectors (lists of numbers); similar meanings land nearby.",
      "track": "core",                    // core | builder
      "elective": false,
      "prereqs": [],
      "sources": ["Raghav Dixit Part A (everything becomes numbers)", "3Blue1Brown Ch5 (first third)"],
      "estMinutes": 35,
      "deliveryModes": ["source", "teach"],   // teach = coach teaches in chat; source = go watch/read;
                                              // codealong = builder live-code; watch-debrief = T6 lectures
      "masteryCheck": "Explain to a smart friend why words become arrows and what makes two words close.",
      "status": "available",              // locked | available | in-progress | mastered
      "masteryScore": null,               // 0-100, last mastery-check score
      "attempts": 0,
      "firstTryMastered": null,           // true if mastered on first attempt
      "codeCompleted": null,              // builder code-along units only: true when the learner's code runs
      "masteredOn": null,                 // date
      "spacedRep": {
        "interval": 0,                    // days until next review
        "ease": 2.5,                      // SM-2-lite ease factor
        "reps": 0,                        // successful consecutive reviews
        "nextReview": null                // date, set after first mastery
      }
    }
  ]
}
```

Field notes:
- **`tier`** is one of `T1` through `T6`. **`track`** on a unit is `core` or `builder`. **`elective`** true means it never blocks anything and never gates graduation.
- **`deliveryModes`** records which doors this unit offers (see the learning engine's unit cycle): `source` (go to the video/article, then debrief), `teach` (coach teaches it in chat), `codealong` (builder live-coding), `watch-debrief` (T6 lectures, watch then defend). Most core units offer `["source", "teach"]`; builder code units add `codealong`; T6 units are `["watch-debrief"]` only.
- **`codeCompleted`** applies only to builder code-along units (and to the code modes of u11 and u14). The builder full-clear graduation check reads this: u11-code and u14-code mean u11 and u14 were completed in code mode.

**Status transitions:**
- `locked` -> `available` when all `prereqs` are `mastered`.
- `available` -> `in-progress` when the unit's lesson starts.
- `in-progress` -> `mastered` when the mastery check passes the threshold.
- A `mastered` unit becomes due for review when `spacedRep.nextReview <= today`.

## progress.json

Gamification and global counters. Updated at the end of every unit and every session.

```json
{
  "xp": 100,
  "level": 1,
  "rank": "Curious Human",
  "streak": 2,
  "longestStreak": 2,
  "lastSessionDate": "2026-07-10",
  "totalMinutes": 70,
  "unitsMastered": 2,
  "graduated": false,
  "fullClear": false,
  "badges": [
    { "id": "first-vector", "label": "First unit mastered", "earnedOn": "2026-07-10" }
  ],
  "history": [
    { "date": "2026-07-10", "minutes": 70, "unitsMastered": 2, "xpEarned": 100, "reviewsDone": 0 }
  ]
}
```

Notes:
- **Ranks** by XP floor: Curious Human 0, Vector Apprentice 250, Gradient Descender 600, Backprop Ninja 1200, Attention Head 2200, Latent Space Navigator 3600, Zero-to-Hero 5500. Level = `floor(xp / 200) + 1`.
- **`graduated`** flips true when every non-elective core unit plus u19 is mastered (the T6 electives never count against this). **`fullClear`** flips true (builder track) when graduation plus u10, u11-code, u12, u14-code, u17 are all done. Zero-to-Hero rank requires `graduated` true (and `fullClear` for a builder), not just the XP floor.
- See the XP, rank, streak, and badge rules in the learning-engine SKILL.

## sessions/YYYY-MM-DD.md

A short human-readable journal for each learning day. Append, do not overwrite, if multiple sessions happen in one day. Used for continuity ("here is what we did last time") and for spaced review context.

```markdown
# LLM Academy: 2026-07-10

## Session 1 (70 min)
- Track: explainer
- Covered: u1 (everything becomes numbers), u2 (the dot product)
- Mastered: u1 (94%, first try), u2 (88%, 2 attempts)
- Struggled with: why the sign of a dot product matters. Re-taught with the "arrows pointing the same way" picture, clicked.
- XP earned: 100. Streak: 2 days.
- Next time: start with a quick review of the dot product, then u3 (what is a neural network).

## Reflection
Strong intuition once the math is translated into plain words. Keep leading with the picture, then show the formula.
```

## Robustness checklist before any state write

- [ ] Did I read the current file first?
- [ ] Is the JSON valid (no trailing commas)?
- [ ] Did I update `lastUpdated` / `lastSessionDate`?
- [ ] If unit status changed, did I regenerate `curriculum.md`?
- [ ] Did I use the real current date, not a guessed one?
